# Soulmate v2: Hermes interview

Goal: rebuild a separate, polished one-question-at-a-time Hermes interview at `v2/`, preserving the existing web app. Browser and any coding/chat agent use the same portable JSON session and question definitions. The user can point Claude/Codex/another agent at a guide and conduct a real live interview, then import that session into the browser. No dependency or model API required.

Visual thesis: an editorial observatory, warm ivory type on near-black with a single amber accent and a large distinctive Hermes wing/radial insignia; calm, confident, spacious.
Content plan: a branded start screen with clear browser/agent paths; single-question workspace with chapter rail and contextual purpose; editable review; downloadable profile and interview handoff.
Interaction thesis: restrained entrance; directional question transitions with reduced-motion support; animated progress and responsive selection states.

## Engine ownership
Create only `v2/interview.mjs`, `v2/questions.json`, `v2/cli.mjs`, `v2/START-HERE.md`, `tests/v2-engine.mjs`. No new dependencies. Export engine API: `createSession(mode='essential')`, `validateSession(value)` returning normalized session or throwing, `getQuestions(session)` (active applicable questions), `getNextQuestion(session)` (unanswered including skipped exclusion), `answerQuestion(session,id,value)` returning updated session, `skipQuestion(session,id)` returning updated session, `buildProfile(session)` returning Markdown. Questions have `id,chapter,title,help,type,options?` options strings; types text/textarea/single/multi. `required` only for essential identity/purpose; branches `when:{id,includes}`; `depth:'deep'` optional. Export `questions` loaded from JSON in Node and browser via fetch or import as compatible; agree with UI worker directly. Session version2 with `mode`, `answers`, `skipped`, timestamps. All functions pure except timestamps; strict IDs/type/length/enum validation, own-property checks, reject prototype keys, max import size. No credentials requested. Preserve edits to branching answers, inactive answers excluded from profile. Unknown version/keys/invalid values fail with readable errors. Profile contains explicit user decisions only; unfilled decisions visibly unresolved, no invented permissions. No executable install scripts. Support readme guide, soul draft, user draft as optional later, primary profile output sufficient.

At least 55 thoughtful questions across Identity, Working relationship, Mission & projects, Knowledge & memory, Tools & access, Team & models, Routines, Communication, Creative work, Home & personal, Reliability & boundaries. Essential mode approximately18-25 questions; deep mode all. Branch questions on chosen interests/tools. Include personality, challenge preferences, context boundaries, authoritative sources and stale/conflicting memory, cost and model routing, specialist roles, research evidence, browser profiles, communication recipients/drafts, automation cadence/timezone/delivery/failure/retirement, backups/recovery, family shared vs private, home actions, accessibility, creative outputs, task completion proof. Never assume a selected interest grants permission.

CLI: `node v2/cli.mjs start --session <file> --mode essential|deep`, `next --session`, `answer --session --id ... --value '<JSON value>'` OR `--value-file`, `skip`, `status`, `export --session --out <md>`. Atomic updates, no overwrite existing start/export without explicit flag. Machine-readable JSON stdout incl errors, nonzero failure. Guide tells an agent to ask one question at a time, wait for actual user answer, use exact values, clarify ambiguity, never answer on user behalf, offer skip/deep switch, export JSON browser import. Tests prove branching, skip/revisit, malicious imports, invalid enum/type/version, CLI roundtrip and error atomicity. Do not touch existing app or infra. No Git push.

## UI ownership
Create only `v2/index.html`, `v2/app.mjs`, `v2/styles.css`, `tests/v2-browser.mjs`. Use shared engine API above; coordinate with engine worker. Serve via local static HTTP (document this later). Offline/no third-party assets/CDNs/analytics. Stunning responsive accessible wizard, not another long form: landing browser/agent options, essential/deep picker with real counts, one question at a time, clear help and optionality, choice options, custom text fields via distinct questions, Back/Continue/Skip, keyboard accessible, save/resume localStorage with visible persistence failure, chapter navigation, progress answered/active with skips distinguishable. Live review editable question links; profile preview; session JSON export/import with strict engine validation, import confirmation before replacing current work, reset confirmation. Agent mode shows actual guide/CLI instructions and download session; clearly describes agent runs in user's own chat, no fake AI chat. Copy text has fallback error feedback. Session roundtrip must share exact version/API. Export profile markdown and interview JSON. No secrets requested. Explain local storage privately on device and exports contain answers. No automatic network/model/tool actions.

Use local SVG/code emblem if useful, system Georgia/Segoe UI fonts, no dependencies. Motion must respect reduced motion. Mobile no horizontal overflow; touch targets >=44px. Focus moves to question title, field errors accessible, textarea Enter adds newline. Tests use Playwright Chrome; test real browser answer/back/skip/reload/review/import/export plus mobile and external request count. Synthetic answers only. Screenshots output ignored `output/playwright/v2/`.
